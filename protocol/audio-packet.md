# EarPair 音频包格式 v1

EarPair 0.1 用 UDP 单向传输未压缩 PCM：Windows 发送端 → Mac 接收端。默认端口 **47800**。

## 包结构

所有多字节字段都是**小端序**。包头固定 32 字节，后面紧跟音频数据。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | `magic` | ASCII `EARP`（`45 41 52 50`） |
| 4 | 1 | `version` | 当前为 `1` |
| 5 | 1 | `flags` | v1 保留：发送端写 0，接收端忽略 |
| 6 | 1 | `codec` | `1` = 16-bit 有符号整数 PCM，各声道交错存放 |
| 7 | 1 | `channels` | 声道数 1–8（0.1 的发送端固定为 2） |
| 8 | 4 | `streamId` | 发送端每次开始采集时随机生成；变了就表示新的音频流 |
| 12 | 4 | `sequence` | 包序号，每包 +1，到 2³²−1 后回到 0 |
| 16 | 8 | `sampleTime` | 本包第一帧在流中的帧序号（从 0 开始） |
| 24 | 4 | `sampleRate` | 采样率，8000–192000 Hz |
| 28 | 2 | `frameCount` | 本包帧数，1–4096 |
| 30 | 2 | `reserved` | 写 0 |
| 32 | … | `payload` | `frameCount × channels × 2` 字节 |

包的总长度必须正好是 `32 + frameCount × channels × 2`，否则接收端丢弃。

## 发送端约定

- 推荐每包 240 帧：48 kHz 下是 5 ms，立体声包长 992 字节，每秒 200 包，约 1.6 Mbps（含包头）。
- 包长不要超过 1472 字节（以太网 MTU 1500 − IPv4 头 20 − UDP 头 8），避免 IP 分片。立体声 16-bit 下即每包最多 360 帧。
- `sampleTime` 必须连续：下一包的 `sampleTime` = 本包 `sampleTime + frameCount`。
- 采样率或声道数变化、或者重新开始采集时，换一个新的 `streamId`；新流的序号和 `sampleTime` 可以从任意值开始（0.1 发送端从 0 开始）。
- 系统没有声音时，发送端照样持续发送（内容为静音），接收端因此可以把"一段时间收不到包"当作断开。例外是待机：接收端声明支持时，发送端没有声音会停发音频包，只用 HELLO 保持握手，见 `control-packet.md` 的“待机”。

## 接收端行为（0.1）

- **锁定发送端**：正在接收时，忽略来自其他 IP 的包；当前发送端超过 1 秒没有包之后，才接受新的发送端（当前发送端在待机时，看的是它的 HELLO：6 秒没有才接受）。同一 IP 换了 `streamId`（比如发送端重启）会立刻切换。
- **乱序**：按 `sequence` 重新排序。缺一个包时，最多再等 3 个后续包。
- **丢包**：等不到的包记为丢失，这段时间用静音补上，前后各做一次很短的淡出 / 淡入，避免爆音。之后才到的包记为"迟到"并丢弃；重复的包同样计入"迟到"。
- **缓冲**：默认目标 60 ms（可选 30 / 60 / 100 / 150 ms）。攒够目标量才开始播放；缓冲耗尽时输出静音并重新攒，记一次"欠载"。
- **时钟漂移补偿**：两台电脑的声卡时钟总有几十 ppm 的差别。接收端根据缓冲量微调播放速度（最多 ±0.2%），让缓冲长期稳定在目标附近。
- **延迟上限**：缓冲比目标多出 60 ms 以上时（比如 Wi‑Fi 卡顿后一次涌进一堆包），直接丢掉最旧的数据，回到目标值。
- **大缺口**：超过 0.25 秒的缺口不补静音，清空缓冲，从下一包重新开始。

## 测试向量

| 字段 | 值 |
|---|---|
| `streamId` | `0x01020304` |
| `sequence` | `7` |
| `sampleTime` | `480` |
| `sampleRate` | `48000` |
| `channels` | `2` |
| `frameCount` | `2` |
| 样本（交错） | `1000, -1000, 32767, -32768` |

编码结果（40 字节）：

```
45 41 52 50 01 00 01 02  04 03 02 01 07 00 00 00
e0 01 00 00 00 00 00 00  80 bb 00 00 02 00 00 00
e8 03 18 fc ff 7f 00 80
```

Mac 端的单元测试和 `tools/test_sender.py` 都会核对这组字节。

## 以后的版本（计划）

- `codec = 2`：Opus，降低带宽并利用它自带的丢包补偿。
- `flags` 第 0 位：包尾带 HMAC 签名，配合配对码，防止同一网络里的其他设备往耳机里塞声音。
- 接收端回传统计（丢包、缓冲水位），让发送端自适应调整。
